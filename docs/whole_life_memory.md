# 全生活记忆与个性化数据设计

本文件是研究设计。当前代码已提供来源保留导入器和最小记忆训练实验；下述结构化记忆库、检索与版本合并、个人 LoRA、删除传播和完整评测管线尚未实现。

## 覆盖范围

范围包括生活经历、习惯与作息、兴趣与审美、家人朋友和人物关系、计划与承诺、情绪表达、沟通偏好、学习、工作和各类聊天。导入按来源覆盖，不因某段聊天和当前工作无关就丢弃。图片、语音和文件保留原始内容对象及附件引用；导出包中不存在的附件不能由引用恢复，导入器不会自行下载附件。

“全部保留”是对已提供来源的保存要求。它不等于所有内容都成为模型事实，不等于每条消息直接作为监督训练目标，也不等于已经取得整个账号的全部记录。

## 三层数据

| 层 | 保存内容 | 可修改方式 |
|---|---|---|
| 原始档案 | 原始 ZIP/JSON、文件哈希、消息角色、时间、分支、附件和未知字段 | 保留来源；用户删除请求另做显式处理 |
| 可更新记忆 | 带来源的事实、偏好、事件、人物、适用场景与版本关系 | 新版本替代旧结论，保留历史解释 |
| 训练派生物 | 经选择的问答、纠正链、行为偏好样本、时间隔离的评测集 | 可依据来源重新构建；原始来源不靠权重代替 |

初次导入不自动抽取人格、诊断、关系结论或监督学习标签。用户的问题可能是在了解别人的情况，引用文本和角色扮演也可能与本人经历无关。助手陈述只是助手输出；只有来源足以支持时才升级为事实。

## 记忆记录建议字段

每条派生记忆至少包括：

- `memory_id`、`revision`：稳定标识和版本。
- `kind`：事实、偏好、事件、计划、沟通规则等。
- `subject`、`scope`：属于谁、适用于何种生活或工作场景。
- `statement`：可独立理解的具体内容，避免抽象人格标签替代证据。
- `evidence_kind`：本人明确表达、本人确认、引用、助手建议、待验证推断等。
- `source_refs`：源文件哈希、对话 ID、节点 ID、必要的原文位置。
- `asserted_at`、`valid_from`、`valid_until`：何时说出、何时有效。缺失时间保持缺失。
- `status`、`supersedes`：当前、被替代、撤回、冲突待处理。
- `training_eligibility`：是否允许用于行为训练以及理由；这是派生决策而非原文属性。

不能只保留一个没有来源的“性格总评”。例如“今天只想被听见”与“讨论代码时请直接指出错误”可以同时成立，分别影响当时或对应场景的回应。不同日期的偏好变化应允许回答“现在怎样”和“以前怎样”。

## 完整导出与分支

ChatGPT 导出的消息树可能同时含有修改前后的用户问题和重新生成的助手回答。索引需要保留全部分支、父子关系和当前选择路径；当前路径不意味着其它分支从未存在，也不意味着当前路径里的助手回答已经被用户认可。

导入器保存原始输入，输出消息级 JSONL 和统计清单。它不检验平台是否漏导、删帖能否恢复或其它账号是否还有记录。来自多个平台、账号或时间点的导出应分别登记来源，并在后续去重时保留出处。

## 个性化训练的使用方式

稳定的沟通偏好和被用户明确接受的处理方式可作为个人适配候选。动态经历、人物关系、临时安排和精确数字优先放在可更新的记忆库里。需要原句、时间或证据时仍能回到原始消息。

首版建议先检验未裁剪底座的记忆与个性化，再加入结构裁剪对照。全生活场景比单一业务宽，裁剪校准样本也必须覆盖这种广度，不能仅因为近期很少讨论某种主题就判断其参数无用。

原始聊天不能整段无差别训练成“模仿上一位助手”。训练样本需要保留用户纠正链、最终接受版本、场景限制和来源。回答问题时不得借用当时尚未出现的未来消息。

## 数据划分与验收

按时间划分训练和评测，并按对话、事件和相关人物成组检查泄漏。仅把同一段聊天的前后两条随机拆开不够。校准集与裁剪选择用的验证集也要有清楚的用途和边界。

| 检查 | 合成情形 | 期望行为 |
|---|---|---|
| 主体归属 | 帮亲友询问某种情况 | 不误写成用户本人情况 |
| 来源角色 | 助手建议出行，用户未确认 | 不说用户已经出行 |
| 偏好更新 | 早期爱长解释，后来某场景只要步骤 | 根据时间与场景采用新偏好 |
| 情绪与性格 | 某晚暂时不想交流 | 不永久判定不爱社交 |
| 虚构材料 | 用户为小说写第一人称经历 | 不当作真实个人经历 |
| 分支纠正 | 修改提问或撤回约定 | 可查旧版本，当前按有效版本处理 |
| 精确回忆 | 需要原句、日期或随机编号 | 找到来源，缺失时明确不知道 |
| 记忆因果性 | 移除或打乱正确记忆 | 答案随证据合理变化，暴露偷记或猜测 |

分别测量原始导入完整性、必要证据召回、生成回答正确性、引用准确性、偏好符合程度、纠正后的更新情况、响应时间和资源消耗。合成文件测试通过不能证明真实长期记忆表现。

## 删除与更新

显式删除个人资料时，需要跟踪原始档案、派生记忆、检索索引、训练样本和模型版本的来源关系。删掉数据库记录不证明模型权重已经忘记相同信息。需要从未含该资料的底座和数据重建适配器，或验证专门的遗忘方法；当前实验未提供这种保证。

## 存放约定

公开 Git 仓库只放通用代码、合成数据、无个人内容的设计和验证说明。真实导出、整理数据、日志、私人适配器与模型检查点放私有存储。忽略文件只是避免误加入的辅助措施，正式提交仍应审查文件清单和内容。
