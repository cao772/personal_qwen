# 个人资料来源、覆盖范围与证据分层

私人模型的资料可以覆盖生活、表达习惯、兴趣、个人选择和工作经历。每份材料都应说明来自哪里、覆盖什么，以及哪些内容仍不可见；“能记起相关信息”不能作为“已取得全部聊天原文”的证明。

## 1. ChatGPT 可见记忆、历史检索与账号导出

ChatGPT 的记忆会选择与当前回答相关的信息，不保留每次对话的所有细节；记忆摘要也未必列出全部可引用来源。当前对话收到的记忆、一次相关历史检索的结果，都不能证明完整历史已经枚举或导出。[官方说明：Memory in ChatGPT](https://help.openai.com/en/articles/8590148-memory-in-chatgpt)

| 来源 | 可以确认什么 | 不能据此宣称什么 |
|---|---|---|
| 当前对话可见的消息 | 当前实际提供的文本与角色 | 其他窗口、其他账号或所有历史均已读取 |
| 可见记忆或记忆摘要 | 系统保存或概括的部分背景、偏好 | 摘要中的每句话都是用户原话，或没有遗漏 |
| 相关历史检索 | 本次返回的来源与片段 | 已遍历全部聊天；没有结果就代表从未说过 |
| 账号可用的数据导出归档 | 实际取得的归档文件及可解析记录 | 所有设备、账号、附件和不可见内容均包含在内 |

需要原文语料时，应取得账号实际可用的导出归档，再依据文件清单核对覆盖范围。导出方式与内容以当前产品和实际归档为准；不要用记忆摘要替代原始对话，也不要把一次检索命中集命名为“全部历史”。

## 2. 本机 Codex 原始会话与生成记忆

ChatGPT 网页记忆与本地 Codex 记忆分别存储。本地 Codex 只从符合条件的历史聊天中生成记忆，处理可能延后；当前活动或短暂会话等可能不参与，因此生成记忆并不是全部聊天原文。[官方说明：Memories](https://learn.chatgpt.com/docs/customization/memories)

官方文档说明，本地记忆位于 `CODEX_HOME` 下，默认根目录是 `~/.codex`；盘点时应分别检查 `memories/` 和 `memories_v2/` 是否实际存在。版本与迁移状态会影响使用哪个目录；目录可能包含生成摘要及支持证据，应保留各自来源。[本地记忆存储说明](https://learn.chatgpt.com/docs/customization/memories)

| 本机材料 | 本项目处理方式 |
|---|---|
| 实际存在的原始会话记录 | 先辨认当前版本的真实结构，再提取用户可见对话；不预设统一格式 |
| `memories/` | 单独登记、单独导出，标明生成记忆来源，不改写为用户自述 |
| `memories_v2/` | 与上一目录分别盘点，重叠内容通过来源关联和哈希核对 |
| 未发现或不可解析的记录 | 记录缺口与原因，不补造原文、不推断为“没有历史” |

CLI 或 IDE 能运行、账号已登录、某个会话目录为空，都不足以证明已取得其他设备或云端的全部 Codex 记录。本文不假设固定的 `sessions` 文件格式，也不提供所谓“官方统一会话导出命令”。

## 3. TraceMemo 微信文字原文

以下是本项目的归属规则，具体字段含义仍需对照实际导出结构及已确认的账号身份：

- 原始导出文件保留不变；解析出的消息保留会话标识、消息标识、发送者、原始时间和来源定位。
- `is_self=true` 只有在导出账号归属已核实时，才能标记为用户本人发送。
- `is_self=false` 表示其他参与者，不能映射为模型的 `assistant`，也不能作为用户本人的性格、偏好或经历。
- 归属不明时标记为待核对，不根据称呼、语气或聊天对象自动认定发送者。
- `quoted_text` 单独保存为引用内容，并尽可能关联被引用消息及原作者；不能视为当前发送者本人的断言。转发内容同样保留转发关系。
- 文本归档没有包含的语音、图片、附件或历史范围，应列为覆盖缺口；不能从文字 ZIP 推断已经覆盖全部微信历史。

## 4. 原文、摘要和推断分层

下列等级是本项目的数据约定，不是平台官方评级；等级描述来源性质，不保证陈述本身真实。

| 来源等级 | 内容 | 使用约束 |
|---|---|---|
| `L1_original` | 从已确认来源提取的用户可见原文 | 保留说话者、引用关系和定位；助手回复仍是助手的内容 |
| `L2_summary` | 平台记忆或模型生成的摘要 | 保留摘要生成来源及可用的原文引用；缺少原文时不得伪装为直接引语 |
| `L3_inference` | 助手对习惯、偏好、人物或事件的推断 | 单独标记推断及依据，不自动升级为用户确认事实 |

同一事项可以同时有三层记录。摘要或推断更新时不覆盖原文；支持证据只有与原始记录核对后，才能作为可追溯的原文片段。用户明确纠正应作为带适用范围与时间的新记录保留，避免把旧状态或单次要求扩展成永久偏好。

每份来源至少记录 `source_type`、`source_level`、相对来源路径、原始文件 `sha256`、字节数、采集时间和解析状态。消息保留原始时间及会话内定位；文件修改时间只说明文件状态，不能代替消息发送时间。时间缺失时保留未知，不补造。

## 5. 可直接交给本机 Codex 的任务

```text
请在本机为个人语料建立可追溯的来源清单，源文件只读。
输出仅写入我指定的 PRIVATE_OUTPUT_DIR，不上传或连接任何远程主机。
1. 只确认实际 CODEX_HOME；未设置时检查默认 ~/.codex，不打印完整环境或读取配置文件。
2. 盘点实际存在的会话记录，以及 memories/、memories_v2/；记录路径、数量、可读性和格式判断。
3. 不假设固定 sessions 格式；仅针对已辨认的格式提取，无法辨认的列为未解析。
4. 对纳入的合法来源记录原始文件 SHA256、字节数、文件时间、可确认的消息时间范围和来源定位。
5. 分别导出用户可见对话与生成记忆摘要；保留真实角色、时间、引用关系和来源等级，助手推断单列。
6. 排除 auth.json、token、credentials、config、私钥及其他凭据文件；不打包整个 Codex home。
7. 对话中若含密钥或凭据，导出副本需遮盖并记录遮盖位置，不改源文件；不导出内部推理或环境快照。
8. 给出已处理、跳过、失败及重复项的清单；结论只覆盖本机已盘点且可解析的材料，不宣称全设备或云端全量。
```

原始来源、导出副本和覆盖清单应留在指定的私有位置。公开仓库仅保存处理代码、通用规则和不含真实个人资料的样例；不能因记忆生成系统已有脱敏机制就省略导出副本的检查。
