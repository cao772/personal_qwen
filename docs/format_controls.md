# 作者元数据与字符串表示：合成配对诊断

这组工具准备小型、完全虚构的阅读材料，用于检查模型是否把显示名当成身份或答案，以及输入表示方式是否改变回答。它不读取个人历史，不检索记录，不训练模型，也不改现有读取器提示。

当前状态为 `prepared_not_executed`。生成输入和合成合同测试通过，都不等于模型已经运行或能力已改善。

## 固定设计

八个模拟情景覆盖生活否定、改期、本人和聊天对象的事实归属、工作多子问、未知细节、引用归属、学习计划纠正，以及临时情绪与长期交流偏好。所有参考答案均由这些合成原文给出；它们不是用户经历、用户性格或训练样本。

每个情景使用四个二元因子的全组合，得到 16 个输入；再加一个无显示名参照。总计 **8 × 16 + 8 = 136 条输入**。

| 因子 | 两个水平 | 保持不变的内容 |
| --- | --- | --- |
| 显示名碰撞 | 普通合成显示名 / `assistant` | 同一条消息的本人／他人归属、正文与引用 |
| 字符串序列化 | 普通字符串 / JSON 引号表示 | 解码后的显示名、正文、引用字符串 |
| 作者块位置 | 正文前 / 正文后 | 作者块全部内容、正文、引用、消息顺序 |
| 额外 `is_self` 字段 | 不呈现 / 明确呈现布尔值 | 原先的本人／他人标签和真实主体 |

JSON 表示因子统一作用于显示名、正文和引用；它检查这一组字段的序列化效应，不能单独归因于某一个引号或模型内部机制。时间和消息边界标记保持一致。

显示名 `assistant` 在四个情景中属于本人，在另外四个情景中属于聊天对象。其归属只由合成来源的 `is_self` 决定，显示名不是聊天 API 的角色。问题及参考答案不要求复述显示名。无显示名参照仅移除显示名字段，保留作者块、本人／他人标签及其余格式。

本人／他人碰撞分组使用不同情景，只做分组描述；碰撞主体没有作为第五个因子交叉，不能据此单独归因哪个主体更容易被误读。

四个因子各有 64 组配对，加上 8 组显示名有无配对，共 **264 组预声明对照**。每组对照只改变一个已声明的因子，使用相同问题、消息、参考答案与判分标准。完整原句始终呈现，不做截断和篇幅竞争；不同表示的字符和 token 数不保证相同。

## 生成文件

将生成器放在仓库的 `experiments/format_controls.py` 后：

```bash
python experiments/format_controls.py \
  --out /path/to/new-synthetic-controls \
  --reader-file experiments/evidence_reader.py
```

输出目录必须不存在。默认使用目录 `700`、文件 `600` 权限。

| 文件 | 内容 | 能否交给读取器 |
| --- | --- | --- |
| `cases.jsonl` | 仅 `id/question/correct`，`correct` 保存合成来源原文 | 是 |
| `answer_key.jsonl` | 参考答复、必要要求、禁止误读及判分规则 | 否 |
| `condition_map.jsonl` | 情景、因子、源与证据指纹 | 否 |
| `contrasts.jsonl` | 预声明的左／右输入 ID、单一变化因子和固定项 | 否 |
| `source_catalog.json` | 虚构情景、原始正文、引用及权威主体 | 否 |
| `manifest.json` | 文件哈希、生成器指纹、必需读取器指纹、运行与分析要求 | 否 |

输入 ID 为不含可读条件名的确定性哈希，输出顺序固定混排。条件名、判分标准和参考答复不会进入问题或输入消息。输入原文包含作答所需事实；这是阅读任务必要的证据，不是参考答复泄漏。

## 待执行模型对照

在已有授权模型环境中沿用原始本地模型、原提示和生成设置：

```bash
python experiments/evidence_reader.py \
  --model /path/to/existing-local-model \
  --cases /path/to/new-synthetic-controls/cases.jsonl \
  --out /path/to/new-synthetic-answers.jsonl \
  --mode research --prompt-version original --conditions correct \
  --max-input-tokens 4096 --max-new-tokens 192
```

使用已有设备预检与单 GPU 入口，不切换日用客户端，不加载个人适配器。实际 tokenizer 检查输入上限，超限直接报错；不能以字符统计替代真实 token 记录。生成器不执行以上命令，当前没有模型分数。

## 冻结判读方式

参考答复允许等义自然中文，不要求逐字复述。正确回答需满足全部必要项、主体归属一致、没有列出的禁止误读。未知学费应明确资料不足；其它有明确依据的问题不能只拒答。

评分时先按不含条件映射的 case ID 和冻结规则判读，再关联 `condition_map.jsonl` 与 `contrasts.jsonl`。因格式本身可见，隐藏映射不能声称完全盲法。单次模型判读不等于独立人工验收。

分别记录以下结果，不以某一项代替其它项：

- 实质答案是否正确，必要子项是否齐全。
- 是否仅复制元数据，特别是显示名和本人／他人标签；这与包含相关事实的正常归属回答不同。
- 是否把本人和聊天对象的事实互换，或把引用归给发送者。
- 是否编造未知内容、忽略否定、沿用已经撤销的安排。

对每个因子报告全部配对的修复、退步、保持正确和保持错误数量，并给出八个情景各自的结果；显示名碰撞另按本人／他人分组。变体共享情景，**136 条输入不是 136 个独立任务**，64 组配对也不是 64 个独立情景。

这是一组针对已观察到的故障类型设计的合成开发诊断，不能作为个性化、长期记忆或新生活材料的泛化验收。冻结后不依据真实题的成绩改动本版；任何新规则需另存版本并说明修改依据。

固定的记录与作者边界用于保证每组配对只改变指定因素。这套受控合成表示没有逐字复现早期生产输入格式；观察到的效应首先只适用于这套表示，不能直接解释其它格式的全部退步，也不能把未复现某种错误解释成它在旧格式里不存在。

## 合成合同检查

```bash
python -B -m unittest -v test_format_controls
```

检查包含：每条配对仅改变指定因子、原文反序列化一致、权威主体不随显示名变化、无显示名参照仅删名字字段、参考答复改变不影响模型输入、输入指纹、唯一性与可重复生成。检查不加载模型或 tokenizer。

## 与既有格式连接及运行核验

另有[冻结格式的合成桥接](format_bridges.md)：相同八个情景分别通过旧格式、原打包器普通名字和原打包器碰撞名字，共 24 条，和本矩阵合计 160 条。桥接不改变本矩阵的 136 条冻结输入。原打包器中的名字配对只改显示名，旧格式与原打包器的比较则是复合格式差异。

真实运行后使用[运行核验与盲判包](format_run_audit.md)，以事先记录的 manifest SHA256 绑定输入、原 reader 和回答，再按冻结要求判读。模拟输出只用于程序合同测试，不能作为模型结果。

## 研究收束

完成这一轮有限诊断后，若发现可复现且能迁移的因素，只作一次针对性修正并另取材料验证。若效应依赖多个因素交互、改善与退步互换，或只修好合成反例，保留已有格式并结束本轮格式搜索。不要为追逐开发题总分继续扩增变体。

来源正确且信息完整时仍存在的主体、否定、不确定状态和多子问错误，可用于定义阅读训练目标；训练与验收需要另外的材料。交流偏好和人格适配的数据工作不必等待格式完美，且应与个人事实正确性分别评估。
