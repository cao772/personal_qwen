# 共享 GPU 主机：只读检查与 GPU1 前台运行

这两个脚本只操作**当前主机**，不会 SSH、安装依赖、下载模型、结束进程、重置 GPU 或启动服务。公开代码不内置用户名、主机名、地址或其他用户的进程资料。脚本尚未在用户目标服务器运行。

## 只读检查

```bash
bash scripts/preflight_server.sh \
  --workspace /PATH/TO/OWNED_WORKSPACE \
  --model-dir /PATH/TO/LOCAL_MODEL \
  --python /PATH/TO/EXISTING_VENV/bin/python
```

上面的目录都是**占位符**；请替换成实际存在、已确认的路径。三个参数都可以省略；没有 `--model-dir` 时不查找模型。输出 JSON，包括当前主机与用户、显卡 UUID/显存/利用率、按 GPU 汇总的计算进程数量与显存、根目录/当前用户主目录/`/home`/`/data` 的文件系统空间、指定 Python 的包版本，以及明确指定模型目录内固定文件名的元数据。进程统计不输出姓名、PID、程序名或命令行。

依赖检查仅查询包元数据，不导入 torch、不创建 CUDA 上下文。模型检查不读取模型内容，也不递归扫描其他目录或其他用户文件。GPU 查询或指定解释器检查失败时退出码为 `1`；缺少某个训练包会如实列出，脚本不安装。

## 默认只验证

```bash
bash scripts/run_on_gpu1.sh \
  --expected-user YOUR_USERNAME \
  --expected-host YOUR_HOSTNAME \
  --workspace /PATH/TO/OWNED_WORKSPACE \
  -- /PATH/TO/EXISTING_VENV/bin/python YOUR_SCRIPT.py
```

必须通过 `--expected-user`、`--expected-host` 明确传入当前用户名与预期短主机名。工作目录必须事先存在，属于当前用户且可写；脚本不创建工作区，也不自动选择磁盘。默认 dry-run 不创建锁、缓存、临时目录或训练进程。

## 明确执行一个前台命令

确认路径、脚本和参数后，在同一个命令中加入 `--execute`。具体模型校准或训练参数由对应程序决定，本脚本不会自行选择训练数据。

GPU 检查先按**物理 index 1**读取 UUID，再按该 UUID 查询并绑定 `CUDA_VISIBLE_DEVICES`。程序内部只可见这一张卡，使用 `cuda:0`；内部 `cuda:1` 不再表示原来的第二张物理卡。

### 固定的阻断条件

- 以 root 身份运行、用户名/主机名不匹配、工作目录不存在/非本人所有/不可写。
- 无法查询 GPU 或解析进程列表，UUID 映射变化，出现不确定状态。
- GPU1 的计算进程 CSV 或 XML 全部进程列表中存在任何进程；即使利用率为 0，也拒绝启动。
- 已用显存超过 **512 MiB**，即使进程列表为空。所谓 defunct 或残留分配不会被视为空闲；脚本不尝试清除。
- GPU1 空闲显存少于 **20 GiB**，或利用率仍非零。
- 工作区文件系统可用空间少于 **20 GiB**，或使用率达到 **95%**。不会转而选择其他磁盘，因此不会自动选用已接近满载的 `/data`。

GPU 和磁盘的最低剩余容量可分别使用 `--min-gpu-free-gib`、`--min-disk-free-gib` 调整；调整不会绕过“进程列表必须为空”和“已用显存最多 512 MiB”的条件。本版没有容忍残留显存的试验模式。

检查会进行两次观察，并在执行分支取得本工作区锁后再次检查。锁只防止使用**同一个工作区、同一脚本**的并发运行；它不是跨用户的 GPU 调度锁，不能阻止其他人随后启动任务。

执行时使用 `umask 077`，缓存和临时目录明确放在指定工作区下，直接 `exec` 前台命令，不使用 shell 字符串求值、不后台化。该脚本不会自行调用 sudo、杀进程、启动 vLLM 或视觉服务。它也不是代码沙箱：被调用程序自己的绝对路径、网络行为和环境变量修改仍由该程序决定。

训练前的实际空间预算和训练参数仍需以本机检查及模型大小为准；这些脚本的检查成功不等于训练完成或模型质量通过。
