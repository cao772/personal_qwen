# 数据说明

`train_demo.jsonl` 与 `eval_demo.jsonl` 全部是人工编写的合成格式示例，覆盖工作、生活、人物归属、情绪、偏好更新和虚构内容，不是用户真实历史。2001 年时间戳只用于演示先后顺序，不表示真实事件。它们不能支撑有效的记忆能力结论。

公开仓库不含个人需求原话或真实聊天。私人数据请置于仓库之外；不要把聊天导出的索引直接当成已清洗好的训练样本。

## 最小记忆训练格式

每行一个 JSON：

```json
{"timestamp":"2001-01-01T01:00:00Z","question":"项目甲当前采用哪一版？","answer":"采用第二版。","memories":["项目甲最初用第一版。","后来明确确认第二版替代第一版。"]}
```

memories 是当前样本允许访问的记录字符串列表。时间、项目、来源和撤销关系应明确写入记录；不要把答案或未来信息伪装成早期记忆。首版没有自动构造长期数据库，调用方负责给出在问题时间前真实可见的记忆集合。

## 建议正式数据

- 校准数据：`{"text":"一段有来源的中文场景与正确处理过程"}`。覆盖本人日常生活与工作，以及必须保留的语言、人物归属、否定、时间和代码能力。
- 个性化数据：请求、旧回答、纠正、最终接受版本及适用范围。
- 记忆数据：问题提出前的记录、问题、依据和正确答案。
- 训练/验证按时间隔离，并留出全新实体、随机编号和撤销/更新情形。相同问题不能只换格式同时出现在训练与验证集。
- 保存角色区别：用户确认、助手猜测、工具实际结果、未验证建议、引语和虚构材料不可混为事实。
- 稳定习惯可用于个人适配；进度、日期、配置等动态事实保留可更新的原始记录，不能只存在于参数。
- 性格表达保留场景和时间；单次情绪不等于永久人格，亲友的情况不能归到本人。

全生活范围、来源字段与评测设计见 [whole_life_memory.md](../docs/whole_life_memory.md)。完整消息导入器与记忆训练器之间尚无自动提取和审核管线。

## 核验范围

示例文件可做格式及流程检查。实际回答质量、时间推理、跨项目混淆和长期记忆有效性必须用真实留出集与生成式评测单独验证。
